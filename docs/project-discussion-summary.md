# ملخص النقاش والقرارات — مشروع AI Product Inspection Agent

> هذا الملف يوثّق مسار النقاش الكامل والقرارات النهائية، ليُستخدم كمرجع سريع (Context) عند فتح أي محادثة جديدة أو تسليم المهمة لأي عضو بالفريق أو لوكيل ذكاء اصطناعي للبدء بالتنفيذ.

---

## 1. الفكرة الأصلية (من الوثيقة المرسلة)

نظام Multimodal AI Agent يستقبل من المستخدم:
- نص يصف مشكلة بمنتج، و/أو
- صورة للمنتج المعيب

ثم يحلّل كل مسار بموديل مختص (RNN للنص، CNN للصورة)، يدمج النتائج (Fusion)، ويُخرج تقرير نهائي عبر LangGraph Agent + LLM.

**تعديل أساسي على الفكرة الأصلية:** تم **حذف طبقة الـ3 APIs الخارجية بالكامل** (كانت مبنية على RapidAPI، وحذفها الدكتور كمتطلب). الـAgent الآن لا يستدعي أي خدمة خارجية.

الهدف: تلبية متطلبات ثلاث مواد بمشروع واحد متكامل:
- **NLP** → Dirty Data + RNN + Information Extraction
- **Image Processing** → Preprocessing + Enhancement + Segmentation
- **Deep Learning** → CNN + Training + Evaluation
- إضافة: **AI Agent (LangGraph) + Multimodal Fusion** كطبقة تجمع كل شيء

---

## 2. المشكلة الجوهرية التي تم اكتشافها

الـDatasets المقترحة أصلًا (MVTec AD للصور، Dataset شكاوى نصية منفصلة) **غير مترابطة إحصائيًا** — لا توجد عيّنة واحدة فيها نص وصورة لنفس الحالة الفعلية. هذا يجعل أي "Multimodal Fusion" حقيقي (على مستوى التدريب المشترك) غير ممكن بدون حل هذه الفجوة.

تم طرح 3 بدائل ومناقشتها:
1. Fusion معماري فقط (كل نموذج يتدرب لوحده، الدمج فقط بالـAgent وقت الاستدلال).
2. الاعتماد الكامل على CESAMARD (Dataset حقيقية بها نص+صورة مترابطين، لكنها أضعف لمتطلبات Image Processing).
3. **(القرار النهائي)** بناء Dataset مدمجة بأنفسنا.

---

## 3. القرار الحاسم: بناء Dataset اصطناعية مدمجة (Synthetic Paired Dataset)

بدل البحث عن Dataset جاهزة، نستخدم **صور MVTec AD الحقيقية** (بقوة annotations الرسمية) ونولّد **نص شكوى مطابق برمجيًا** لكل صورة اعتمادًا على label الصورة (نوع المنتج + نوع العيب):

```
صورة MVTec (Bottle, Scratch) → مولّد نص (Templates + تنويع + "تلوّث" متعمد) → نص شكوى مطابق
```

النتيجة: عيّنة موحّدة = `صورة + نص + label متطابق`، وهذا يحل 3 مشاكل دفعة واحدة:
- تكامل حقيقي 100% بين الوسائط (Data-level pairing حقيقي، مو Fusion وهمي).
- الحفاظ الكامل على جودة MVTec وannotations الرسمية لمادة Image Processing.
- تلبية متطلب "Dirty Data" لمادة NLP (نحن من يتحكم بمستوى التلوّث اللغوي بالنص المولّد).

---

## 4. القرارات التقنية النهائية

| المحور | القرار | السبب |
|---|---|---|
| **مصدر الصور** | MVTec AD (فئة واحدة نبدأ فيها، مثل Bottle أو Hazelnut) | أنظف نتائج، annotations دقيقة، ترخيص CC BY-NC-SA 4.0 (استخدام أكاديمي غير تجاري) |
| **مصدر النص** | مولَّد برمجيًا اعتمادًا على labels الصور (Templates + حقن ضوضاء) | يضمن التطابق الكامل + يلبي متطلب "Dirty Data" |
| **مهمة RNN** | Two-stage / Multi-task: رأس 1 (شكوى/لا شكوى) + رأس 2 (نوع المشكلة: Quality/Packaging/Price/Delivery/Damage/Other) عبر Shared Encoder | يغطي التصنيف الثنائي والمتعدد معًا بكفاءة حسابية |
| **مهمة CNN** | Segmentation/Localization فعلي باستخدام الماسكات الرسمية المرفقة مع MVTec (Supervised، وليس البروتوكول البحثي الرسمي Unsupervised) | يستغل annotations MVTec بالكامل، ويعطي نتائج مباشرة وقابلة للشرح |
| **Multimodal Fusion** | حقيقي على مستوى الـEmbeddings: دمج تمثيل RNN + تمثيل CNN قبل طبقة قرار نهائية موحّدة | ممكن فعليًا بفضل تطابق البيانات المُصمَّم بالخطوة 3 |
| **LangGraph Agent** | بدون أي API خارجي: `Input → Text/Image Analyzer → Fusion → Context Builder → LLM → Response` | الـAPI حُذف كمتطلب من الدكتور |
| **الفريق والوقت** | شخصان، عمل متوازي قدر الإمكان | معطى واقعي من الفريق |

## 5. نقاط لم تُحسم بعد / افتراضات مفتوحة

- **عدد فئات MVTec النهائي**: البدء بفئة واحدة، مع إمكانية إضافة فئة ثانية أو ثالثة لاحقًا إذا سمح الوقت.
- **بنية RNN الدقيقة** (Shared Encoder بنموذج واحد مقابل نموذجين منفصلين): تم ترجيح Shared Encoder (Multi-task Learning) كتوصية، دون اعتراض من الفريق — يُعتمد كافتراض نهائي ما لم يُطلب تغييره.

## 6. قرارات الجولة الثانية (إغلاق النقاط المفتوحة)

| النقطة | القرار النهائي |
|---|---|
| **مزوّد الـLLM (عقدة الـAgent الأخيرة)** | متوفر مسبقًا: بيئة محلية لدى الفريق مُعدّة أصلًا مع أكثر من مزوّد عبر OpenRouter — المطلوب فقط ربط برمجي (Integration) بعقدة الـLLM بالـGraph، لا قرار إضافي مطلوب |
| **خوارزمية RNN** | **BiLSTM** (بدل LSTM عادي وحيد الاتجاه) — أفضل فهم للسياق بجمل الشكاوى القصيرة بدون تعقيد إضافي كبير |
| **Tool Use بالـAgent** | **نعم، تُضاف أداة محلية واحدة بدون إنترنت**: Lookup لسياسة الاسترجاع/الضمان (Return/Warranty Policy) من ملف CSV محلي حسب فئة المنتج، تُستدعى شرطيًا فقط عندما يكون `Requested_Action` متعلق باسترجاع/استبدال. هذا يُظهر نمط Tool Use بمعمارية الـAgent دون أي اعتماد على خدمة خارجية |

توضيح مهم: اللبس بخصوص "لا API" — القرار الأصلي بحذف الـAPI كان خاصًا فقط بالـ3 APIs الخارجية (RapidAPI لبيانات/أسعار المنتج) التي حذفها الدكتور. أما **استدعاء الـLLM بعقدة الـAgent الأخيرة فهو جزء أصيل من فكرة LangGraph Agent من البداية** ولا علاقة له بذاك القرار.

---

## 7. خارطة الطريق المعتمدة (9 مراحل)

1. الإعداد (هيكلة المشروع + تحميل MVTec + بيئة العمل الموحدة)
2. بناء مولّد النصوص المطابقة لصور MVTec (Dataset Engineering)
3. NLP Pipeline (تنظيف + تدريب RNN Two-stage)
4. Image Processing Pipeline (تحسين وتجهيز الصور + توثيق بصري قبل/بعد)
5. Deep Learning (تدريب CNN Segmentation + تقييم IoU/Dice)
6. Information Extraction (استخراج الحقول المنظمة من مخرجات RNN)
7. Multimodal Fusion (دمج التمثيلات + طبقة قرار موحدة)
8. LangGraph Agent (بناء الـGraph + System Prompt + Context Engineering)
9. الواجهة + الاختبار الشامل End-to-End + التوثيق النهائي والتسليم
